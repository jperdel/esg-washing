# Vocabulario ESG canónico — única fuente de verdad.
#
# FORMATO: forma natural en singular, una por línea. NO lematizar a mano.
#   · El plural lo añade automáticamente el regex ("emission" cubre "emissions").
#   · Espacios y guiones son intercambiables ("net zero" cubre "net-zero").
#   · Las líneas que empiezan por # y las vacías se ignoran.
#
# ESTE FICHERO ALIMENTA DOS CONSUMIDORES CON REPRESENTACIONES DISTINTAS:
#
#   1. lexical_document_filter._ESG_KW_RE — regex sobre el texto CRUDO del PDF.
#      Usa las formas de aquí tal cual, con tolerancia de plural y separadores.
#
#   2. config.ESG_KEYWORDS — vocabulario TF-IDF sobre el corpus LEMATIZADO.
#      NO se lee de aquí directamente: se lee de esg_terms_lemmatized.txt, que
#      genera scripts/build_lexicons.py pasando cada término por el MISMO
#      TextProcessor que preprocesa el corpus. Así el vocabulario y el corpus
#      hablan siempre la misma lengua.
#
# >>> DESPUÉS DE EDITAR ESTE FICHERO, EJECUTA:  python scripts/build_lexicons.py
#     El script avisa de los términos que no sobreviven al preprocesado.
#
# Los términos con dígitos (scope 1, article 8, ifrs s1) NO van aquí: el
# preprocesado elimina los tokens numéricos, así que nunca podrían puntuar en
# el TF-IDF. Viven en _EXTRA_PATTERNS de lexical_document_filter.py, que solo
# actúa sobre texto crudo.
#
# Estado: los términos de la auditoría externa (880 zonas de 4 memorias 2023)
# YA están incorporados. Cada candidato se midió sobre los 343 informes
# completos —ocurrencias, documentos, empresas, países y cuota de la empresa
# que más lo usa— antes de admitirlo. Resultado: 102 aceptados por dispersión,
# 18 frecuentes y polisémicos resueltos con colocaciones, y 22 sectoriales
# apartados en esg_terms_sectorial.txt.
#
# La especificación que reporta el paper sigue siendo el vocabulario de 154
# términos; esta ampliación se documenta como prueba de robustez.
