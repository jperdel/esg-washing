This appendix discloses every element of our pipeline at the level of detail
whose absence \S\ref{sec:original} records for the antecedent: the code, the
files each stage reads and writes, the parameters, the seeds, the output
schema and the software versions. Everything below describes the adopted
specification: our vocabulary with its sectoral entries,
$\SUS = \susdens$ and $w_q = w_h = 0.5$ (\S\ref{sec:lexicon},
\S\ref{sec:index}). The paper reports one run of the pipeline, and every
number in it comes from that run or from the analysis scripts that read it.

\subsection{What is in the repository and what must be regenerated}
\label{sec:repro-regenerate}

The repository holds the code (\nolinkurl{main.py}, \nolinkurl{src/},
\nolinkurl{scripts/}), every lexicon and metadata file (\nolinkurl{metadata/})
and this paper. The directories \nolinkurl{data/} and \nolinkurl{results/} are
excluded by \nolinkurl{.gitignore}: no PDF, no extracted or preprocessed text
and no output file is versioned. A reader who wants to regenerate the paper's
numbers needs three things from outside the repository. First, the 344 PDFs,
placed as \nolinkurl{data/pdf/<COUNTRY>/<Company>/<file>.pdf}; the two folder
names become the \texttt{País} and \texttt{Compañía} fields and are the keys
on which \nolinkurl{metadata/muestras_informes.xlsx} (document type) and
\nolinkurl{metadata/empresas_supersector.csv} (supersector) are joined, so the
folder names must match those files exactly. Second, the environment of
Table~\ref{tab:repro-deps}. Third, two environment variables:
\texttt{ESG\_RUN\_TAG=v3} and \texttt{ESG\_INCLUDE\_SECTORAL=1}. Both
\nolinkurl{src/config.py} and \texttt{run\_suffix()} in
\nolinkurl{src/lexical_document_filter.py} turn them into the suffix
\texttt{\_v3\_sec} on every pipeline path; the second also adds the sectoral
term and pattern files to the extraction regex and the sectoral lemmas to the
scoring vocabulary. Without them the pipeline scores the base vocabulary only
and writes to the unsuffixed directories. We ran every script with
\texttt{PYTHONIOENCODING=utf-8} as well, which only affects console output on
Windows.

Everything else is regenerated by the code: \nolinkurl{main.py} produces the
pipeline outputs (Table~\ref{tab:repro-pipeline}) and the scripts of
Table~\ref{tab:repro-analysis} produce every number and figure the paper
reports.

\nolinkurl{src/config.py} refuses to start if a generated lexicon is missing
and logs a warning if its source file is newer, so a vocabulary edit that is
not followed by \nolinkurl{scripts/build_lexicons.py} is reported rather than
silently scored with the old lemmas. The adopted run was executed in three
calls: extraction; then preprocessing on that extraction
(\texttt{run\_extraction=False}), with the protected phrases of row 5 of
Table~\ref{tab:repro-defects}; then measurement on the stored preprocessed
text (\texttt{run\_preproc=False}), with rows 6 and 7 in place and the stored
file rewritten under the NUL rule of row 8. None of rows 5--8 alters the
extraction regex, and each call reads only what the previous one wrote.

\subsection{Analysis layer}
\label{sec:repro-analysis}

No number in the paper is read off the pipeline by hand. The scripts of
Table~\ref{tab:repro-analysis} read the pipeline outputs, write every quotable
quantity to \nolinkurl{results/analysis_v3/} or \nolinkurl{results/stability_v3/},
and draw the figures into \nolinkurl{paper/figures/}. Because
\nolinkurl{results/} is not versioned, the paper never \verb|\input|s a file
from it; every table was transcribed from these outputs. The table gives a
valid running order. Three dependencies fix it:
\nolinkurl{robustness_v3.py} reads the outputs of both stability scripts,
\nolinkurl{extraction_stats_v3.py} reads a per-document file written by
\nolinkurl{analysis_v3.py}, and \nolinkurl{figures_v3.py} reads the outputs of
\nolinkurl{analysis_v3.py} and \nolinkurl{stability_v3_e2e.py}. The other

\nolinkurl{corpus_composition.py}, \nolinkurl{vocab_v3_stats.py},
\nolinkurl{validity_v3.py}, \nolinkurl{critique_v3.py} and

Three runtimes need a gloss. \nolinkurl{stability_v3_e2e.py} ran in 19
minutes with its cache of per-paragraph lemmatised counts already built; it
reuses the cache unless called with \texttt{--rebuild}, and by the script's own
estimate rebuilding it adds about 40 minutes. \nolinkurl{analysis_v3.py} took 74 seconds with the
PDF word counts already cached; a first run reads the full text layer of all
344 PDFs. And \nolinkurl{validity_v3.py} and \nolinkurl{critique_v3.py}
recompute the components from the text with \texttt{ESGSIAnalyzer} and check
them against \texttt{results.csv} before reporting anything, which is what
their runtime buys.

\paragraph{Other scripts and outputs not reproduced.} No script of the
analysis layer compares the adopted run with any other run. The repository still holds the scripts that produced candidate lists during the
construction of the vocabulary (\nolinkurl{build_consensus*.py},
\nolinkurl{build_vocab_v3*.py}, \nolinkurl{build_kwic_sample.py}); no number in
this paper comes from them except the two dispersion constants that
\S\ref{sec:lexicon-criteria} quotes from the last. The analysis outputs
identify firms only by anonymous positions (\texttt{<Industry>-NN}). The keys
that link a position to a company folder are written to files whose names end
in \texttt{\_internal} (\nolinkurl{doc_level_internal.csv},
\nolinkurl{firm_ids_internal.csv}, \nolinkurl{extraction_by_doc_internal.csv},
\nolinkurl{extraction_internal.json}, \nolinkurl{corpus_composition_internal.csv});
the company folder names also appear in \texttt{results.csv} itself and in the
PDF word-count cache. None of these is reproduced in the paper.

\subsection{Determinism}
\label{sec:repro-determinism}

Extraction, preprocessing and measurement together are a pure function of
the PDFs, the lexicon files of Table~\ref{tab:repro-pipeline} and the pinned
versions of Table~\ref{tab:repro-deps}: no network call, no external API, and
no random draw anywhere on this path (\S\ref{sec:extraction}). The one
non-trivial control-flow step, the deduplication that takes the 344
preprocessed reports to 343, keeps the first of any two reports whose
\texttt{clean\_text} has the same MD5 hash (\S\ref{sec:data}). Which of the
two identical files of the duplicated report counts as first follows the
order in which the file system lists the JSON files; on our machine the file
without the \texttt{\_repaired} suffix is kept. The choice changes the
\texttt{Documento} string of one row and nothing else, since the two texts are
identical. Row order in \texttt{results.csv} follows the same listing; no
score depends on it.

Randomness enters only in the analysis layer, and every draw is seeded:

\begin{itemize}
  \item \emph{Wild cluster bootstrap} (\S\ref{sec:index-inference}):
        \nolinkurl{analysis_v3.py}, $B = 9{,}999$, seed $20260925$
        (\texttt{SEED}, \texttt{N\_BOOT}), NumPy \texttt{default\_rng}, one
        Rademacher weight per firm and replication.
        \nolinkurl{robustness_v3.py} calls the same function with the same seed
        for its trend $p$-values.
  \item \emph{Firm bootstrap of the convergent-validity correlations}
        (\S\ref{sec:validity}): \nolinkurl{validity_v3.py}, 9{,}999 samples of
        firms with replacement, seed $20260925$, percentile 95\% intervals.
  \item \emph{Random vocabulary deletions, frozen extraction}
        (\S\ref{sec:robustness-lexicon}): \nolinkurl{stability_v3.py}, seed
        $20260918$, 2{,}000 draws at each deletion share (10, 20, 30, 40 and
        50\% of the entries) and 5{,}000 size-matched draws for each designed
        deletion.
  \item \emph{Random vocabulary deletions, both modes}
        (\S\ref{sec:robustness-lexicon}): \nolinkurl{stability_v3_e2e.py},
        seed $20260919$, 1{,}000 draws at each deletion share and 1{,}000
        size-matched draws for each designed deletion.
\end{itemize}

In both stability scripts all draws come from one generator in a fixed
sequence, so a given draw is reproducible only by running the whole script,
not in isolation. The amplification and dilution demonstrations of
\nolinkurl{critique_v3.py} (\S\ref{sec:measurement}) involve no draw: the
source report is the one at the median of $\susdens$, and the dilution filler
is taken deterministically from its 50 most frequent non-vocabulary tokens.

One documented quantity cannot be regenerated from the repository. The
calibration of the navigation filter (\S\ref{sec:extraction-nav}) is recorded
in the docstring of \texttt{\_is\_navigation}, but the script that computed it
is not committed; its rates are recorded there but not reproducible, and the
paper reports neither. The yield figures of
\S\ref{sec:extraction-yield}, by contrast, are computed on all 343 reports by
\nolinkurl{analysis_v3.py}; no sample is involved.

The LDA topic model (\nolinkurl{src/topic_modeler.py}) is the only
stochastic component of the pipeline code, and it is switched off
(\texttt{run\_lda=False}). Its \texttt{fit()} builds the model with
\texttt{random\_state=None}, so it is unseeded; its stability analysis is
gated behind \texttt{LDA\_N\_SEEDS>0} and never invoked at the repository's
setting \texttt{LDA\_N\_SEEDS=0}. LDA feeds none of \SUS, \SEN, \QUANT,
\HEDGE, \ESGSI\ or \ESGSIext, and no output of it is used in this paper.

\subsection{Output schema}
\label{sec:repro-schema}

The file \nolinkurl{results/metrics_v3_sec/results.csv} is \texttt{;}-separated,
UTF-8, 343 rows by 17 columns, listed in Table~\ref{tab:repro-schema}. The row
count is already net of the duplicated report that deduplication removes
(\S\ref{sec:data}); nothing downstream needs to drop a row by hand. The column
names and the country values are Spanish (\texttt{ALEMANIA}, \texttt{FRANCIA},
\ldots); \texttt{Compañía} is the company folder name and equals the
\texttt{Empresa} column of \nolinkurl{metadata/empresas_supersector.csv}
exactly.

The last two columns, \texttt{Etiqueta} and \texttt{Etiqueta\_ext}, are a
remnant of the antecedent's classification rule: the pipeline still writes, for
each report, a label derived from the sign of each score. \textbf{They are not
used anywhere in this paper}: no script of Table~\ref{tab:repro-analysis}
reads them, no figure or table reports them, and no threshold is applied to
either score (\S\ref{sec:artefact}). A reader regenerating the results should
ignore them.

The score columns are rounded to four decimals, so a score recomputed from the
rounded component columns does not match the stored one exactly. \QUANT\ and
\HEDGE\ have standard deviations of the order of $10^{-3}$, so recomputing
\ESGSIext\ from their rounded columns reproduces it only to about $10^{-2}$.
The analysis scripts therefore recompute the components from the text at full
precision wherever precision matters, and check the recomputation against the
stored columns.

\subsection{Vocabulary and lexicons as published artefacts}

Every lexicon that feeds a score in this paper is a plain-text or CSV file in
the repository, loaded at run time rather than transcribed into the paper:
\begin{itemize}
  \item the v3 vocabulary, \nolinkurl{metadata/ESG_terms_v3.csv}: 434 entries,
        each with its type (term or pattern), pillar and sectoral flag, plus
        bookkeeping columns from its construction that no score reads
        (\S\ref{sec:lexicon});
  \item its four exported files, the input of the extraction regex:
        \nolinkurl{esg_terms.txt}, \nolinkurl{esg_terms_sectorial.txt},
        \nolinkurl{esg_patterns.txt}, \nolinkurl{esg_patterns_sectorial.txt};
  \item the scoring vocabulary that \SUS\ and \BREADTH\ actually count,
        \nolinkurl{esg_terms_lemmatized.txt} and
        \nolinkurl{esg_terms_sectorial_lemmatized.txt}: $V = 399$ entries, of
        which 140 unigrams, 224 bigrams, 34 trigrams and one four-gram;
  \item the 11 protected phrases, \nolinkurl{esg_protected_phrases.txt}, as
        regular expression and replacement token;
  \item the hedge lexicon, \nolinkurl{lm_hedge.txt}: the 495 distinct forms

  \item the 189-entry supplementary stopword list,

  \item the document-type and supersector maps,
        \nolinkurl{muestras_informes.xlsx} and

The files a third party would need to recompute every number in this paper
are the same files that produced them.

run and are fixed in the working tree. The adopted run includes all eight.
We report them because most produced a plausible-looking number instead of an
error, and that failure mode is the one most likely to survive review in
dictionary-based text measurement.

The general lesson is not specific to this codebase. In dictionary-based
measurement, a mis-specified component returns zero, or a plausible non-zero
number, rather than raising an error: a token filter, a lemmatisation
mismatch, a vectoriser default or a stopword list can each silently remove an
entire category of matches while the pipeline runs to completion and writes a
number that looks exactly like a low-incidence finding. None of the defects in
Table~\ref{tab:repro-defects} raised an exception or an out-of-range value;
each was found only by checking a component against text known in advance to
contain the pattern it was supposed to detect, or by recomputing a stored
quantity from its inputs.

A reader who checks out \texttt{54a419d} exactly gets the scoring vocabulary

condition for reproduction.
